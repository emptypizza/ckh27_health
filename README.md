# ckh27_health

Apple 건강에서 내보낸 파일을 차트로 살펴보고 증상, 수면, 복용한 약을 날짜별로 기록하는 개인 건강 관리 앱입니다. 파일을 여는 일부터 기록을 암호화해 보관하는 일까지 브라우저 안에서 처리합니다.

- 앱: <https://emptypizza.github.io/ckh27_health/>
- 테스트 페이지: <https://emptypizza.github.io/ckh27_health/tests/>

기록을 정리하는 도구이며 진단이나 처방을 대신하지 않습니다.

## iPad에서 암호로 배포 기록 열기

개인용 PIN 링크를 받았다면 iPad의 Safari에서 그 링크를 열고 **열람 PIN** 여섯 자리를 입력합니다. 처음 열기에 성공하면 Safari가 암호화된 등록 정보를 기억합니다. 이후 같은 Safari에서는 일반 앱 주소에서도 같은 PIN을 사용할 수 있습니다. 사이트 데이터를 지우거나 다른 브라우저를 이용할 때는 개인 링크를 다시 여세요. 개인 링크는 해당 기록을 열 수 있는 등록 정보이므로 본인만 보관하세요.

기존의 긴 열람 암호도 사용할 수 있습니다. 등록한 기기에서는 **열람 암호로 열기**를 선택하세요. 배포 기록은 읽기 전용이며 **배포 기록 잠그기**를 누르거나 페이지를 새로고침하면 다시 잠깁니다.

### 배포 기록의 열람 암호 변경

첫 화면이나 배포 기록 대시보드에서 **열람 암호 변경**을 누릅니다. 저장소 관리자는 현재 열람 암호와 새 암호를 입력해 모든 기기가 사용하는 배포 기록을 다시 암호화할 수 있습니다. 새 암호는 12자 이상입니다. [암호 변경 화면](https://emptypizza.github.io/ckh27_health/password.html)

변경 화면에서 GitHub의 fine-grained personal access token을 발급할 수 있습니다. 저장소 선택에서 **Only select repositories → ckh27_health**를 지정하고 **Contents → Read and write**를 선택합니다. 토큰은 해당 파일에 대한 GitHub API 요청에만 사용합니다. 현재 암호와 새 암호는 기기에서 처리하고, GitHub에는 새 암호문을 전송합니다. [GitHub 토큰 발급 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)

변경 화면에서 새 파일이 실제 사이트에 배포됐는지 확인할 수 있습니다. iPad에서 PIN을 계속 쓰려면 변경할 때 원하는 여섯 자리를 입력하고, 배포 후 표시되는 새 개인 링크를 iPad에서 한 번 여세요. 이미 내려받은 파일과 Git 이력에 남은 이전 버전은 그때의 암호로 열 수 있습니다.

## 내 기기의 ZIP 또는 XML 열기

1. iPad **건강** 앱의 사이드바에서 **요약 → 프로필 → 모든 건강 데이터 내보내기 → 파일에 저장**을 선택합니다.
2. 이 웹앱의 첫 화면에서 **건강 파일 선택**을 누르고 ZIP을 엽니다. 압축을 풀어 둔 경우 상세 XML 또는 `export_cda.xml`도 열 수 있습니다. ZIP에 함께 들어 있는 파일은 한 번에 읽습니다.
3. 요약 카드에서 분류를 선택하거나 **측정 항목**에서 다른 항목을 고릅니다. **7일·30일·90일·전체**는 해당 항목의 마지막 기록일을 기준으로 합니다. 차트 구간을 누르면 값을 확인할 수 있고 **차트 수치 표로 보기**와 **원본 기록**에서는 수치, 시각, 출처를 확인할 수 있습니다.
4. 처음 연 파일은 미리보기입니다. **내 기록에 보관**을 눌러 암호를 설정하거나 기존 암호로 잠금을 풀면 이후에도 같은 브라우저에서 볼 수 있습니다. 잠금을 푼 상태에서는 **Apple 건강 → 파일 추가**로 다음 내보내기를 합칠 수 있습니다.

각 측정 항목을 원본 단위로 표시합니다. 혈압은 수축기와 이완기를 짝지어 표시하고, 수면은 단계별로 선택할 수 있습니다. 같은 내보내기를 다시 열거나 상세 XML과 CDA를 함께 가져와도 같은 측정이 늘어나지 않습니다. Apple 건강 기록과 직접 작성한 일지는 각각 보존되며 암호화 백업에는 둘 다 포함됩니다.

ZIP은 최대 256MiB, 내부 XML은 파일당 32MiB, 합계 64MiB까지 열 수 있습니다. 암호화 보관은 정규화한 전체 기록이 3MB 이내일 때 지원합니다.

## 사용 방법

1. 일지를 쓰거나 파일을 보관하려면 처음에 **건강 기록 암호**를 6자 이상으로 만듭니다. 다음부터는 이 암호로 잠금을 풉니다. 암호가 짧거나 짐작하기 쉬우면 백업 파일을 얻은 사람이 기록을 열 수 있으니, 길게 만들수록 안전합니다.
2. **일일 기록**에서 날짜를 고르고 기분·기력·스트레스(1~5), 몸무게, 수면, 체온, 맥박, 혈압, 증상, 복용한 약, 식사, 배변, 메모를 아는 것만 입력해 저장합니다. 아래 **최근 흐름**에서 최근 7·14·30일의 수면·기분·기력·스트레스 평균과 날짜별 기록을 볼 수 있습니다.
3. **기본정보**에 생년월일, 혈액형, 키, 알레르기, 진단받은 질환, 현재 처방, 의료기관을 적어 둡니다.
4. **진료 요약**은 고른 기간의 기록과 진료 때 물어볼 질문을 글로 정리합니다. 복사하거나 `진료요약-날짜.txt` 파일로 받아 가져갑니다.
5. 다 쓰면 **기록 잠그기**를 누릅니다.

저장하지 않은 내용이 있으면 날짜를 바꾸거나 잠글 수 없습니다. 먼저 저장하거나 입력을 취소하세요.

## 기록이 저장되는 곳

- **배포 기록**은 GitHub Pages에 암호문으로 게시됩니다. 페이지가 암호문을 내려받고, 입력한 열람 암호로 브라우저 메모리에서 복호화합니다. 배포 기록을 열어도 브라우저의 개인 일지에 쓰지 않습니다.
- **직접 작성한 일지와 추가한 파일**은 보관을 선택한 브라우저에 암호화해 저장합니다. 앱은 입력한 암호나 건강 기록을 서버로 전송하지 않습니다.
- 저장할 때 암호에서 만든 키(PBKDF2-SHA256 600,000회)로 암호화(AES-GCM 256)합니다. 암호는 어디에도 저장하지 않습니다.
- **암호를 잊으면 기록을 열 수 없고 복구할 방법도 없습니다.**
- 열람 암호를 아는 사람은 다른 기기에서도 같은 배포 기록을 볼 수 있습니다.

### 백업과 다른 기기에서 쓰기

- **암호화 백업 받기**는 `건강기록-암호화백업-날짜.json` 파일을 내려받습니다. 파일 내용도 암호화되어 있습니다.
- 다른 기기나 브라우저에서는 처음 화면의 **암호화 백업 선택**으로 그 파일을 고르고 같은 암호를 입력해 복원합니다.
- 브라우저 데이터를 지우면 기록도 지워집니다. 이 앱은 `emptypizza.github.io`의 다른 페이지와 브라우저 저장 공간을 함께 쓰므로, 백업을 주기적으로 받아 두는 것이 안전합니다.
- 기록 형식과 암호화 방식은 fortune-report의 건강 관리 기능과 같습니다. 그 앱에서 받은 암호화 백업을 같은 암호로 복원할 수 있습니다.
- 암호를 잊어 처음부터 다시 시작하려면 브라우저의 사이트 데이터에서 `ckh27_health:vault:v1` 항목을 지웁니다. 지운 기록은 되돌릴 수 없습니다.

### 건강 기록 JSON 추가

잠금을 푼 상태에서 **건강 기록 JSON 추가**로 암호화하지 않은 기록 파일(1MB 이하)을 합칠 수 있습니다. 이미 기록이 있는 날짜는 그대로 두고 없는 날짜만 추가하며, 기본정보는 비어 있는 항목만 채웁니다.

```json
{
  "version": 1,
  "profile": { "birthDate": "1990-05-15", "bloodType": "A+", "heightCm": 172.5 },
  "entries": [
    { "date": "2026-11-21", "sleepHours": 8, "mood": 4, "symptoms": "두통", "meals": "아침 거름" }
  ]
}
```

- `profile`: `birthDate`, `bloodType`, `heightCm`, `allergies`, `conditions`, `medications`, `clinician`
- `entries`의 각 항목: `date`(필수), `weightKg`, `sleepHours`, `mood`, `energy`, `stress`, `temperatureC`, `pulse`, `systolic`, `diastolic`, `symptoms`, `medications`, `meals`, `bowel`, `notes`

## 로컬에서 실행

빌드 과정이 없습니다. 저장소 폴더에서 정적 서버를 띄우고 브라우저로 엽니다.

```sh
python3 -m http.server 8000
```

<http://localhost:8000/> 으로 엽니다. 브라우저는 https와 localhost에서만 암호화 기능을 주므로, `index.html` 파일을 직접 열면 동작하지 않습니다.

## 테스트

`tests/` 페이지(<http://localhost:8000/tests/>)를 열면 Apple 건강 파일 읽기, 중복 처리, 기록 검증, 진료 요약, 암호화·복원 테스트가 그 브라우저에서 실행되고 결과가 표시됩니다. 테스트에는 인공적으로 만든 예시를 사용합니다.

## 구성

| 파일 | 내용 |
| --- | --- |
| `index.html` | 앱 페이지와 콘텐츠 보안 정책 |
| `css/app.css` | 스타일 |
| `js/health.js` | 기록 형식, 입력 검증, 진료 요약 생성 |
| `js/health-vault.js` | 암호로 기록을 암호화하고 푸는 부분 |
| `js/apple-import.js`, `js/apple-model.js` | Apple 건강 ZIP·XML·CDA 읽기와 병합 |
| `js/apple-view.js`, `css/apple-health.css` | Apple 건강 요약 카드, 추세 차트, 표와 원본 보기 |
| `js/app.js` | 화면과 동작 |
| `js/icons.js` | 아이콘 |
| `tests/` | 브라우저에서 실행하는 테스트 |

## 배포

`main` 브랜치에 push하면 GitHub Pages가 저장소 루트를 그대로 배포합니다.
